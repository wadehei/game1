# 未提交批次审查结论 + 修复方案

## Context

当前工作区有一批未提交改动（基于今日已提交的安全批 b0c24fa）：**后端双 token 改造**（新增 authController/tokenService，落实 STRIDE SP-05）+ **前端类型化重构**（首页拆 6 组件+gameCatalog、坦克页拆 useTankEngine、battle 组件 any→具体类型）。经 3 路并行审查 + 人工复核，结论：**拆分重构本身质量高（功能零丢失），但双 token 改造是半成品**——前端完全没跟上，存在 2 个 P0 阻断。

## 审查发现（按严重度）

**P0（阻断）**
1. **登录契约断裂**：后端 3 个登录接口已返回 `{accessToken, refreshToken, expiresIn, userInfo}`（loginController.ts:49,72,118），前端仍读 `result.token`（api/user.ts:20,34）→ 存 "undefined" 进 localStorage → 全站 401。且前端无任何 /refresh 调用。
2. **refresh token 可当 access token 用**：middleware/auth.ts:62,99 只验 userId 是 number，不校验 `type==='access'`，30 天 refresh token 可直接作为 HTTP 凭证且不受黑名单约束；wsServer.ts:93 同样不验 type。
3. **typecheck 大面积报错**（CI 必跑）：S2CEvent 未导出却被 import、GameState 联合类型直接取属性（room.vue/useMemberState/GamePanel）、levelDefaults 返回类型收紧打爆 puzzle/balloon/tank 等数值运算、spy/uno/blackjack/zjh 事件载荷标注与后端实际不符。

**P1（真实 bug）**
4. **房间 WS 鉴权前后端不一致**（HEAD 已存在，人工复核确认）：前端发首条 `{t:'auth'}` 消息（67e9c5d 引入），后端只认 URL `?token=` 且无该消息处理器 → 连接必被 4001 关闭。
5. logout-all 在 Redis 模式只遍历内存 Map，实际撤不掉（tokenService.ts:194-212）。
6. blackjack_phase/zjh_phase 的 betOptions/raiseSteps/stakeCap 前端不落库 → 正常开局 blackjack 下注按钮不渲染（靠后端自动下 10 兜底）。
7. tank 引擎 `bindCanvas` 无人调用 → H5 点击坐标偏右 ~15px（useTankEngine.ts:591-593）。

**P2（顺带修）**：logout 不验 refresh token 归属；STRIDE 文档把 SP-05 过度声明为"已实现"；死代码（generateUserToken/verifyAccessToken/TankControls.vue 死文件）；wsTypes 字段名错（uno 应为 penalty、strokes 应为 seq）；quiz 断线快照重建用旧字段名；ProfilePinSection 401 文案；前端 src 下 41 个 git-ignored 陈旧 .js 产物会遮蔽 .ts。

## 修复步骤

### Phase 1 — 地面真值
跑 `children-games-backend` `npm test`、`children-games-frontend` `npm run typecheck`，核对审查报告的类型错误清单（审查在 plan 模式无法执行命令，以实际输出为准）。

### Phase 2 — 后端（~7 文件）
- `src/middleware/auth.ts`：新式 token（带 type 字段）强制 `type==='access'`，无 type 存量长期 token 走兼容路径；`src/ws/wsServer.ts:93` 连接鉴权同样校验 type + jti 黑名单。
- `src/controllers/authController.ts`：logout / logout-all 校验 `refreshPayload.userId === req.userId`。
- `src/services/tokenService.ts`：Redis 模式下用 per-user jti 集合（SADD/SMEMBERS+DEL）实现真正的 revokeAll；`generateTokenPair` 从 authController 下沉至此（消除 controller→controller 依赖）；清死导入。
- `src/controllers/loginController.ts`、`src/utils/auth.ts`：清死代码（generateUserToken、verifyAccessToken）。
- `docs/security/STRIDE_THREAT_MODEL.md`：SP-05 改为"部分实现（迁移期存量 token 不可撤销）"。
- 测试：auth.test.ts 补「refresh token 当 Bearer → 401」用例；tokenService.test.ts 补 Redis revokeAll 用例。

### Phase 3 — 前端（~20 文件，用户已确认方案 A：同批接入双 token）
- **登录链路**：`api/user.ts` LoginResult 改双 token 结构并新增 refresh/logout API；`store/user.ts` 存 accessToken（沿用 `token` key）+ refreshToken（新 `refresh_token` key）；`utils/request.ts` 401 时单飞（single-flight）调 `POST /api/user/refresh` 换新 token 并重试原请求一次，失败才清 storage；登出时通知后端。
- **WS 鉴权**：`composables/useRoomWs.ts` 改为 URL 携带 `&token=`（后端已支持），删除首条消息 auth，更新注释。
- **typecheck 修复**（逐项跑 vue-tsc 核销）：wsTypes.ts 导出 S2CEvent、uno 排名字段改 penalty、strokes 改 seq；room.vue 初始 state 对齐 GomokuGameState + 按 gameType 收窄联合；useMemberState.ts/GamePanel.vue 同模式收窄；SpyGame/UnoGame/BlackjackGame/ZjhGame 事件载荷标注按后端实际载荷修正；useRoomWs.ts CloseEvent 签名；levelDefaults.ts 返回类型回退为可数值运算的形状。
- **顺带修复**：useRoomEvents.ts 落库 betOptions/raiseSteps/stakeCap；room.vue quiz 快照重建改用 qid/text/index/total；ProfilePinSection 错误文案取 `e.response.data.message`；useTankEngine.ts onMountedSetup 改调 `bindCanvas` 并清冗余返回；删死文件 TankControls.vue；删 41 个陈旧 .js/.js.map；index.vue 清空 .card 规则。

**明确不做（下批）**：refresh rotation/重用检测、/refresh 独立限速、shared 包 ws 类型全量同步、AdminLogin 2FA。
