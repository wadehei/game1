## P0：游戏插件化重构（必做前置）

### 现状问题
- `roomManager.Room.game` 直接是 `GomokuState`；`wsServer` 的 `move/resign/rematch` 分支写死了五子棋逻辑
- 房间人数无 per-game 约束（五子棋 2 人对局，其它游戏人数不同）
- 加新游戏 = 改 wsServer 核心，容易弄坏已上线的五子棋

### 目标设计
新建 `src/ws/games/` 目录，每个游戏一个文件，实现统一接口：

```ts
export interface GameHandler {
  type: GameType;                    // 'gomoku' | 'quiz' | 'draw' | 'spy' | 'uno'
  minPlayers: number;                // 少于该人数不能开局（ready 校验改用它）
  maxPlayers: number;                // 座位上限（超出自动转观战）
  allowSpectators: boolean;
  create(): GameState;               // 初始游戏状态
  seedPlayers(seats: number): void;  // 开局时分配角色/颜色/词等
  onAction(room: Room, member: Member, action: string, payload: any): {
    error?: string;                  // 非法操作原因（回给操作者）
    broadcast?: Msg[];               // 广播事件
    toMember?: { userId: number; msg: Msg }[];  // 点对点事件（私发）
    ended?: { winnerSeat: number; reason: string } | null;
  };
  serializeFor(room: Room, viewer: Member): any;  // 按观看者序列化（为 P3/P4 私发信息预留）
}
```

### 改造点
| 文件 | 改动 |
|---|---|
| `roomManager.ts` | `Room.game` 类型改为 `any`（由 handler 创建）；`MAX_MEMBERS` 改从 handler 读；`memberList` 增加 rematch 之外的 per-game 字段 |
| `wsServer.ts` | `ready/move/resign/rematch` 中游戏逻辑抽到 handler；动作路由表：`{ move: 'gomoku', quiz_answer: 'quiz', draw_stroke: 'draw', ... }`；开始条件用 `handler.minPlayers`；快照的 game 段改调 `serializeFor(viewer)` |
| `gomoku.ts` | 包装成第一个 `GameHandler`，行为与现在完全一致（回归保障） |
| 前端 `room.vue` | 游戏区抽成动态组件 `<component :is="gameComponent">`，公共部分（座位条/聊天栏/操作区/确认弹层）留在容器；`useRoomWs` 不变 |

### 验收
`tests/ws-protocol.mjs` 22 项全部保持通过（五子棋零行为变化）。

## P1：答题对战（题库 PK）

### 玩法定稿
- **2~8 人同时竞答**（非轮流）：每局 N 题（默认 10，建房可选 5/10/15），每题 15 秒
- 计分：答对 +10，按作答速度加成（剩 15s 内答对，每剩 1 秒 +0.5，封顶 +5），答错/超时 0 分
- 题型：四选一单选（v1）；分类可选（建房时勾选，如 综合/影视/历史）
- 结束按总分排名，支持再来一局（换一组题）

### 状态机
```
waiting →(全员ready)→ question(n) →(deadline或全员答完)→ reveal(n, 3s) → question(n+1) → ... → finished
```
- 题目推进由服务端 setTimeout 驱动；房间解散时清定时器
- 断线重连：重连者拿到当前题目 + 剩余时间 + 已答题情况（自己是否已答）；错过按未答计

### 数据模型（新表）
`quiz_questions`：id / category / difficulty / text / options(JSON) / answer(0-3) / createdAt
- 走现有 `initModels` sync + `syncMissingColumns`，无迁移脚本

### 协议增量
```
C→S  quiz_answer  { qid, choice }        // 每题限答一次
S→C  quiz_question { index, total, qid, text, options, deadline }   // 不含答案！
S→C  quiz_result    { qid, answer, delta: [{userId, gained, total}] }
S→C  quiz_final     { ranking: [{userId, nickname, total}] }
```

### 后台管理
- 管理面板新增「📚 题库」Tab：列表/搜索/单题编辑 + **JSON 批量导入**（格式 `[{text, options, answer, category}]`）
- 路由挂 adminMiddleware，复用 `api/admin.ts` 的 client

### 前端
`components/battle/QuizGame.vue`：题目卡 + 四个选项按钮（答对绿/答错红高亮）+ 环形倒计时 + 右侧实时积分榜 + 揭晓过渡（谁对谁错 + 得分动画）

### 验收
扩展 ws-protocol 测试：双人开局 → 抢答判分（先答对多得分）→ 超时未答 → 全流程到 ranking；含「揭晓前协议中不出现答案」的防作弊断言。

**预估：后端 1 天 / 前端 1 天 / 题库+后台 0.5 天**

## P2：你画我猜

### 玩法定稿
- 3~8 人，轮流当画家；每人一轮（N 人 = N 个回合，可配置 1~2 圈）
- 画家从 3 个候选词选 1 个开始画；猜的人打字猜（复用聊天输入）
- 每回合 90 秒：全部猜对 / 时间到 / 画家跳过 → 回合结束亮词
- 计分：猜对者按速度 +10~+5，画家每被猜对一人 +3
- 提示：词长 + 分类；30 秒后自动揭示一个字

### 实时画布同步（关键技术点）
- 画家端采样笔迹增量（pointerdown/move → 折线段），**10Hz 批量上报** `{points:[], color, width}`，服务端直接转发（不合并）
- 服务端保存本回合 `strokes[]` 全量历史；**新进/重连玩家先发全量历史重放**，再进实时流
- 防滥用：仅当前画家可发；单条 ≤4KB；每秒 ≤30 条（超频丢弃并提示）

### 协议增量
```
C→S  draw_pick     { wordIndex }          // 画家选词
C→S  draw_stroke   { points, color, width }
C→S  draw_undo / draw_clear
C→S  draw_skip                            // 画家跳过（扣自己2分）
C→S  guess { content }                    // 走聊天通道，服务端判定
S→C  draw_round   { drawer, wordLen, category, candidates?(仅画家), deadline }
S→C  draw_stroke  (转发给非画家)
S→C  draw_history { strokes }              // 新进/重连重放
S→C  guess_result { userId, correct }      // 猜对者对其余人显示"猜对了！"
S→C  draw_round_end { word, scores }
```
- 猜对后该玩家后续猜测不再广播（防止他剧透）；画家猜对者名单实时更新

### 词库
- v1 用后端 JSON 文件（`src/ws/games/draw-words.json`，~200 词，分 3 档难度、带分类）；P1 的题库后台模式成熟后再挪表管理

### 前端
`components/battle/DrawGame.vue`：canvas 画板（pointer events + devicePixelRatio 适配）、颜色/粗细/撤销/清空工具条（仅画家可见）、猜词输入、回合状态条

### 验收
协议测试：画家独占校验（非画家发笔画被拒）→ 笔画转发 → 重连重放全量历史 → 猜对判定（大小写/空格归一化）→ 全对提前结束。

**预估：后端 1.5 天 / 前端 1.5 天**

## P3：谁是卧底

### 产品定位（关键决策）
**线上只做「发词 + 计时 + 投票 + 判定」**，描述环节是线下口头进行（大家开语音或面对面）。
理由：文字描述节奏拖沓、失去"说错话露馅"的核心乐趣；做成语音房成本高（媒体服务）。这一定位让纯回合制实现保持轻量。

### 玩法定稿
- 4~12 人；1 卧底（≥7 人时 2 卧底）；平民词/卧底词为一对近义词（如 苹果/梨）
- 每轮：描述阶段（90s 计时，仅提醒）→ 投票（60s，每人一票，可弃权）→ 最高票出局并亮身份（平票：平票者进入 60s PK 陈述后重投，仅限平票者）→ 胜负判定：卧底全灭=平民胜；存活卧底数 ≥ 存活平民数=卧底胜
- 出局者转为观战（可看全局、可聊天，不可投票）

### 关键技术点：按人私发
- 词/身份必须只发给本人 → P0 的 `serializeFor(viewer)` 在此落地：卧底的 snapshot 里 role/word 只在 `serializeFor(自己)` 时出现
- 私发消息（发词）用 `toMember` 通道

### 数据
`spy_word_pairs.json`：~100 对词（平民词/卧底词/分类），与画词库同目录

### 协议增量
```
C→S  spy_vote { target | null }           // null=弃权，每轮一次，可改票
S→C  spy_deal    { role, word }           // 私发
S→C  spy_phase   { phase:'talk'|'vote', deadline, alive[] }
S→C  spy_vote_update { votedCount }        // 只报人数防跟票
S→C  spy_vote_result { counts, out, outRole, nextDeadline }
S→C  spy_final   { winner:'civilian'|'spy', spyWord, spyUserIds }
```

### 验收
协议测试：私发隔离（A 的快照/事件中永不出现 B 的词）→ 改票 → 平票 PK 流程 → 卧底全灭/数量反转两种终局。

**预估：后端 1.5 天 / 前端 1 天**

## P4：UNO

### 玩法定稿
- 2~6 人；108 张标准牌（4 色 × 0-9 ×2 + 跳过/反转/+2 各色×2 + 万能/万能+4 ×4）
- 每人 7 张起手，翻牌堆顶作首张（万能牌重抽）；轮流出「颜色或数字/符号匹配」的牌或摸 1 张（摸到能出可立即出）
- 牌堆摸空重洗弃牌堆；首名出完者胜，其余按手牌罚分排名
- v1 简化：剩 1 张自动广播「UNO!」不设忘喊惩罚；+2/+4 不可叠加质疑

### 关键技术点：手牌隐私
- 每人手牌仅自己可见 → 复用 P3 的 `serializeFor(viewer)`；`your_hand` 私发
- 出牌合法性服务端校验（颜色/数字/符号匹配 or 万能），非法回 error

### 协议增量
```
C→S  uno_play  { cardId, chooseColor? }
C→S  uno_draw                        // 摸1张；能出时立即出或保留
C→S  uno_pass                        // 摸后不能出才可 pass
S→C  uno_hand    { cards }           // 私发
S→C  uno_played  { userId, card, chooseColor?, next, drawCount }  // drawCount 通知被+2/+4者
S→C  uno_turn    { seat, deadline }  // 45s 超时自动摸1张并跳过
S→C  uno_final   { ranking }
```

### 前端
`components/battle/UnoGame.vue`：手牌横排（可出的牌上浮高亮）、弃牌堆 + 牌堆、当前颜色指示灯、方向指示、颜色选择弹窗（万能牌）、超时自动摸牌提示

### 验收
协议测试：手牌私发隔离 → 匹配校验（颜色/数字/万能）→ 功能牌效果（跳过/反转/+2 摸牌链）→ 牌堆重洗 → 首胜判定。

**预估：后端 2 天 / 前端 1.5 天**

## 公共事项

### 断线重连矩阵（每款游戏必须覆盖）
| 游戏 | 重连恢复内容 | 对局中断线处理 |
|---|---|---|
| 五子棋（已上线） | 座位+棋盘+聊天 | 60s 未归判负 |
| 答题对战 | 当前题+剩余时间+自己作答状态 | 错过的题按未答，不判负 |
| 你画我猜 | 笔迹全量重放+已猜名单 | 画家断线：60s 未归跳过其回合 |
| 谁是卧底 | 私发词重发+存活名单+投票状态 | 投票阶段断线：视为弃权 |
| UNO | 手牌重发+桌面牌+当前回合 | 超时自动摸牌跳过（已有机制） |

### 大厅改造（随 P1 一起做）
- 建房改为游戏选择卡片（图标/人数范围/一句话说明），游戏列表从后端 `GET /api/room/games` 拉取（返回各 handler 的 type/min/max/说明），前端不再硬编码
- 房间页容器按 gameType 动态挂载游戏组件

### 战绩系统（全部游戏完成后统一做）
`game_records` 表（gameType/playerCount/ranking JSON/duration/finishedAt），各游戏终局时写入；个人中心加「对战战绩」入口。v1 各游戏先不上，避免分散。

### 每款游戏的统一交付标准
1. `tests/ws-protocol.mjs` 风格的协议测试（新增 `tests/ws-<game>.mjs`），本地全绿
2. 双手机真机走查：建房→加入→断线重连→再来一局→解散
3. 管理后台如涉及（题库），增删改查可用
