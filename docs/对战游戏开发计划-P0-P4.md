## P0：游戏插件化重构（D1，1 天）

**目标**：wsServer 与具体游戏解耦，加新游戏不再改核心代码；五子棋行为零变化。

### T0.1 GameHandler 接口与注册表
- 新建 `children-games-backend/src/ws/games/types.ts`

```ts
export type GameType = 'gomoku' | 'quiz' | 'draw' | 'spy' | 'uno';

export interface ActionResult {
  error?: string;                                   // 回给操作者
  broadcast?: Array<Record<string, unknown>>;       // 广播事件
  toMember?: Array<{ userId: number; msg: Record<string, unknown> }>; // 点对点
  ended?: { winnerSeat: number; reason: string } | null;  // 非空=对局结束
}

export interface GameHandler<S = any> {
  type: GameType;
  title: string;                 // 大厅展示名
  emoji: string;                 // 大厅图标
  desc: string;                  // 一句话玩法说明
  minPlayers: number;            // 达到即可开局
  maxPlayers: number;            // 座位上限，超出转观战
  rematchSwapSeats: boolean;     // 重开是否交换座位（五子棋 true，其余 false）
  create(): S;
  start?(room: Room): ActionResult | void;             // playing 开始时（发词/发牌/抽题）
  onAction(room: Room, member: Member, action: string, payload: any): ActionResult;
  onPlayerQuit?(room: Room, member: Member): ActionResult | void;  // 对局中退出
  serializeFor(room: Room, viewer: Member): Record<string, unknown>;
}
```

- 新建 `games/registry.ts`：`export const gameHandlers: Record<GameType, GameHandler>` + `getHandler(type)`
- 新建 `games/gomoku.ts`：包装现有 `gomoku.ts` 纯逻辑为第一个 handler（move/resign 路由进来），`minPlayers: 2, maxPlayers: 2, rematchSwapSeats: true`

### T0.2 roomManager 改造
- `Room.game: any`；`createRoom` 用 `getHandler(gameType).create()`
- 人数上限：玩家 ≤ `maxPlayers`；总成员（含观战）统一 ≤ 12（替换现有 MAX_MEMBERS=8）
- `Room.timers: NodeJS.Timeout[]` + `addTimer/clearTimers`：游戏定时器统一登记，`disbandRoom` 时全部清除（P1 起使用）

### T0.3 wsServer 路由化
- 动作注册表：`const GAME_ACTIONS: Record<string, GameType[]> = { move:['gomoku'], resign:['gomoku'], ... }`（各游戏往里加自己的 action）
- `ready` 校验改 `players.length >= handler.minPlayers && players.every(ready)` → 开局先 `handler.start?.()` 再广播 `game_start`
- **快照按人序列化**：`broadcast` 内循环对每个在线成员调 `handler.serializeFor(room, member)` 组装各自快照（P3/P4 私发的地基）；`joined` 同理
- rematch：通用重开（`handler.create()` + `handler.start()`），座位交换仅当 `rematchSwapSeats`
- 对局中退出：调 `handler.onPlayerQuit`，返回 `ended` 则广播 game_over

### T0.4 前端容器化
- `room.vue` 游戏区抽为 `<GamePanel :game-type :game-state :my-seat @action="send">`；`GamePanel` 内 `GomokuBoard.vue`（从 room.vue 拆出，纯展示 + emit action）
- 公共件（座位条/聊天栏/确认弹层/操作区框架）留在容器

### 验收与提交切分
- 提交①：T0.1+T0.2+T0.3（后端重构，含 `tests/ws-protocol.mjs` 22 项回归全绿，断言不改）
- 提交②：T0.4（前端拆分，typecheck + build）

### T1.4 游戏 handler（D2 下午~D3）
- 新建 `games/quiz.ts`：

```ts
interface QuizState {
  questions: { qid, text, options, answer, category }[];  // 开局抽取，含答案（仅服务端）
  total: number;
  index: number;                 // 当前题下标
  deadline: number;              // 本题截止时间戳
  answers: Map<userId, { choice: number; ts: number }[]>;  // 每题限答一次
  scores: Map<userId, number>;
  timer: NodeJS.Timeout | null;
}
```

- 开局（`start`）：按建房选的分类随机抽 N 题（默认 10，建房参数 5/10/15）
- `onAction('quiz_answer')` 校验链：phase=playing → 题号一致 → 未答过 → 未超时（服务器时间）→ 记录；**全员答完提前收卷**
- 计分：答对 `+10 + min(5, ceil(剩余秒 × 0.5))`，答错/超时 0
- 题目推进：`setTimeout(reveal→next)` 链，每次 `room.addTimer()` 登记
- 防作弊红线：`quiz_question` 事件与 `serializeFor` 输出中**永不包含 answer**

### T1.5 协议终稿
```
C→S  quiz_answer { qid, choice }
S→C  quiz_question { index, total, qid, text, options[], deadline }
S→C  quiz_answered { userId }                      // 让别人知道你答完了（不透露对错）
S→C  quiz_result    { qid, answer, delta: [{ userId, gained, total }] }
S→C  quiz_final     { ranking: [{ userId, nickname, total }] }
```

### T1.6 前端（D3~D4）
- 建房改造：游戏选择卡片列表（数据源新增 `GET /api/room/games`，返回各 handler 的 type/title/emoji/desc/min/max——T0.3 顺带实现）
- `components/battle/QuizGame.vue`：题目卡 + 选项四宫格（提交后锁定至揭晓，对绿错红）+ 环形倒计时（CSS conic-gradient）+ 实时积分榜 + 揭晓过渡层

### T1.7 测试（D4 下午）
`tests/ws-quiz.mjs`：
1. 双人开局，`quiz_question` 事件无 `answer` 字段（防作弊断言）
2. 先答对者得分 > 后答对者（速度加成）
3. 答错 0 分、重复作答被拒、超时提交被拒
4. 全员答完提前进入揭晓
5. 完整跑完 → `quiz_final` 排名与累计分一致
6. 中途断线重连：拿到当前题 + deadline + 自己已答状态
7. 再来一局换一组题

**提交切分**：①T1.1+T1.2 ②T1.3 ③T1.4+T1.5 ④T1.6 ⑤T1.7

## P2：你画我猜（D5~D7，3 天）

### T2.1 词库（D5 上午）
- `children-games-backend/src/ws/games/draw-words.json`：~200 词，结构 `{ word, category, difficulty(1-3) }[]`；分类：动物/食物/物品/动作/成语

### T2.2 游戏 handler（D5 下午~D6）
- 新建 `games/draw.ts`：

```ts
interface DrawState {
  round: number; totalRounds: number;      // totalRounds = 参与人数 × 圈数(1)
  drawerSeat: number;
  candidates: string[];                    // 画家三选一
  word: string | null; category: string;
  strokes: any[];                          // 本回合全量笔迹（重放用）
  guessed: Set<userId>;
  scores: Map<userId, number>;
  deadline: number;
  phase: 'picking' | 'drawing';
  lastForwardAt: number;                   // 节流
}
```

- 回合流转：`picking`（画家三选一，10s 未选随机）→ `drawing`(90s) → 结束条件：全员猜对 / 超时 / `draw_skip`（画家 -2 分）→ 亮词 → 下一位画家
- 计分：猜对者 `+10 - floor(已耗时/9)`（即 10~5），画家每被猜对一人 +3
- 笔画：仅 `drawerSeat` 成员可发；单条 ≤4KB；**10Hz 服务端节流**（超出直接丢弃）；`draw_undo` 弹最后一条自己的笔画并广播
- 猜词：独立 action `guess`（非聊天），服务端归一化判定（trim/小写/去内部空格）；猜对→不广播其内容（防剧透），改为系统消息广播「XXX 猜对了！」；未猜对→作为普通聊天下转（所有人可见）

### T2.3 协议终稿
```
C→S  draw_pick  { index }
C→S  draw_stroke { points: [[x,y]...], color, width }   // x/y 为 0~1 归一化坐标
C→S  draw_undo / draw_clear / draw_skip
C→S  guess { content }
S→C  draw_candidates { words: [3] }            // 私发画家
S→C  draw_round  { drawerSeat, wordLen, category, deadline }
S→C  draw_stroke  (原样转发给非画家)
S→C  draw_history { strokes }                   // 重连/新观战者全量重放
S→C  draw_undo   { by } / draw_clear
S→C  guess_result { userId, correct }
S→C  draw_round_end { word, scores }
S→C  draw_final { ranking }
```
- 坐标归一化（0~1）：各端屏幕宽度不同，渲染时乘自画布尺寸

### T2.4 前端（D6~D7）
- `components/battle/DrawGame.vue`：canvas（`devicePixelRatio` 适配 + pointer events 抓折线）、画家工具条（6 色/3 粗细/撤销/清空，仅画家可见且 `pointer-events` 控制）、猜测滚动区、回合状态条（当前画家/词长/倒计时）
- 聊天栏照常可用（聊天与猜词并存：guess action 承担猜词，chat 承担闲聊）

### T2.5 测试（D7）
`tests/ws-draw.mjs`：非画家发笔画被拒 → 笔画转发一致（对端收到的点序列 = 画家发的）→ 重连者收到 `draw_history` 且与服务端 strokes 一致 → 猜词归一化（带空格/大小写变体命中）→ 猜对后其后续 guess 不再广播 → skip 扣分 → 全员猜对提前结束。

**提交切分**：①T2.1+T2.2+T2.3 ②T2.4 ③T2.5

## P3：谁是卧底（D8~D10，2.5 天）

### T3.1 词对库（D8 上午）
- `spy-word-pairs.json`：100 对 `{ civilian, spy, category }`（如 苹果/梨、口红/唇彩）

### T3.2 游戏 handler（D8 下午~D9）
- 新建 `games/spy.ts`：`minPlayers: 4, maxPlayers: 12, allowSpectators: false`（卧底人数敏感，观战一律不允许）

```ts
interface SpyState {
  round: number;
  roles: Map<userId, { role: 'civilian'|'spy'; word: string; alive: boolean }>;
  phase: 'talk' | 'vote' | 'reveal';
  deadline: number;
  votes: Map<userId, number | null>;   // null=弃权，可改票
  isRevote: boolean; revotePool?: number[];   // 平票重投时仅可投池内人
}
```

- 发牌：开局随机词对；卧底数 = 人数 ≥7 ? 2 : 1；`spy_deal` 私发
- 轮转：`talk`(90s 定时提醒) → `vote`(60s) → 统计 → 最高票出局（平票 → `isRevote=true`，仅可投平票者，再平则本轮无人出局）→ 出局者 `alive=false` 并公开身份 → 胜负判定：卧底全灭=平民胜；存活卧底数 ≥ 存活平民数=卧底胜 → 否则下一轮 talk
- `serializeFor`：本人可见自己 role/word；已出局者的身份对所有人可见；存活他人的一律不可见

### T3.3 协议终稿
```
C→S  spy_vote { target: number | null }    // 每阶段一次，阶段内可改
S→C  spy_deal  { role, word }              // 私发
S→C  spy_phase  { phase, deadline, alive: [userId], isRevote, revotePool? }
S→C  spy_vote_update { votedCount, total } // 只报数量，防跟票
S→C  spy_vote_result { counts: [{target, count}], out: number|null, outRole?, nextDeadline }
S→C  spy_eliminated { userId, role }       // 出局亮身份（广播）
S→C  spy_final { winner, spyUserIds, words }
```

### T3.4 前端（D9 下午~D10）
- `components/battle/SpyGame.vue`：身份卡（点按翻转看词，防止旁人瞥屏）、存活玩家头像网格（投票阶段点选目标/弃权）、阶段倒计时条、淘汰揭示幕、终局幕

### T3.5 测试（D10）
`tests/ws-spy.mjs`（4 人连接 uid 2/4/6/12）：
1. **私发隔离**：遍历 A 收到的全部事件，永不包含 B 的 role/word
2. 发牌分布：恰有 1 名卧底（4 人局），词对成对
3. 投票/改票/弃权：改票后 `vote_update` 计数正确
4. 出局：最高票者出局且 `spy_eliminated` 的 role 与其 `spy_deal` 一致
5. 平票：进入 revote 且只能投池内目标
6. 终局两种：投出全部卧底=平民胜（可通过连续把票投给已知卧底构造——测试用 SpyState 种子化或读事件推卧底后集中投票）

**提交切分**：①T3.1+T3.2+T3.3 ②T3.4 ③T3.5

## P4：UNO（D11~D13，3.5 天）

### T4.1 牌堆引擎（D11 上午）
- `games/uno/engine.ts`（纯逻辑，可单测）：
  - `buildDeck()`：108 张 `{ id, color: 'red'|'yellow'|'green'|'blue'|'wild', kind: '0'-'9'|'skip'|'reverse'|'draw2'|'wild'|'wild4' }`（每色 0×1、1-9×2、skip/reverse/draw2×2；wild/wild4 各 4）
  - `canPlay(card, top, currentColor)`：wild 恒可；同色/同 kind 可
  - `cardScore(card)`：数字=面值，skip/reverse/draw2=20，wild/wild4=50（终局罚分排名用）

### T4.2 游戏 handler（D11 下午~D12）
```ts
interface UnoState {
  deck: Card[]; discard: Card[];       // 弃牌堆含顶牌
  hands: Map<userId, Card[]>;          // 手牌（serializeFor 私有）
  currentColor: string;
  direction: 1 | -1;
  turnSeat: number;
  drawnThisTurn: boolean;              // 摸过1张后才能 pass
}
```
- 回合 45s 超时：自动摸 1 张并跳过（`room.addTimer` 登记，出牌/摸牌时重置）
- 牌堆空：弃牌堆除顶张外重洗回牌堆
- +2/+4：目标玩家摸对应张数并跳过其回合（v1 不支持叠加质疑）
- 万能牌出牌必带 `chooseColor`
- 首名出完 → 终局，ranking = 各人剩余手牌 `cardScore` 总和升序

### T4.3 协议终稿
```
C→S  uno_play { cardId, chooseColor? }
C→S  uno_draw                            // 摸1张（本回合限一次）
C→S  uno_pass                            // 摸后无牌可出才允许
S→C  uno_hand   { cards }                // 私发（开局/摸牌/每次状态变化都同步）
S→C  uno_played { userId, card, chooseColor?, nextSeat, drawn: { userId, count }? }
S→C  uno_turn   { seat, deadline }
S→C  uno_color  { color }                // 万能选色广播
S→C  uno_final  { ranking: [{ userId, nickname, penalty }] }
```
- 广播的 `uno_played` 不含任何人的手牌；摸牌者私下收到 `uno_hand` 更新

### T4.4 前端（D12 下午~D13）
- `components/battle/UnoGame.vue`：手牌横排（可出牌上浮 + 置灰不可出）、牌堆/弃牌堆、当前颜色色灯、方向箭头（2 人局反转=跳过提示）、万能选色弹窗、超时自动摸牌 toast

### T4.5 测试（D13）
`tests/ws-uno.mjs`：
1. 手牌私发隔离（事件遍历断言）
2. 匹配校验矩阵：颜色匹配✓、数字匹配✓、无匹配✗、万能✓
3. skip：下家被跳过（`uno_turn` 断言）
4. reverse：2 人局等效跳过、4 人局方向翻转
5. draw2/wild4：目标者手牌 +N 且被跳过
6. 牌堆耗尽重洗：构造牌堆只剩 1 张的场景断言重洗发生
7. 首胜判定与罚分排名

**提交切分**：①T4.1 ②T4.2+T4.3 ③T4.4 ④T4.5
