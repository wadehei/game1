## P1：帧率绑定修复 — delta time 化（等价重构，真 bug）

### 背景（已实测）

IAB/高刷环境 rAF 可达 242fps。以"px/帧"计算速度的引擎在 120/144Hz 屏幕上游戏速度成倍，难度失真。参照实现：`src/composables/useTankEngine.ts:307` 已有 dt 先例（`const dt = (now - lastFrameTime) / 1000`），敌方移动已乘 dt，但玩家移动漏乘（见 P1-D）。

**dt 标准写法**（与 tank 一致）：

```ts
let lastFrameTime = Date.now();
const gameLoop = () => {
  const now = Date.now();
  const dt = Math.min((now - lastFrameTime) / 1000, 0.05); // 秒；0.05 上限防后台切回首帧跳变
  lastFrameTime = now;
  update(dt);
  render();
  animationId = requestAnimationFrame(gameLoop);
};
```

要点：
- 位置速度乘 dt；**计时类（倒计时 deadline、spawn 定时器 setInterval）不动**——setInterval 是墙钟，本来就帧率无关。
- `Math.min(dt, 0.05)` 必须加：浏览器后台节流后切回，dt 会是几秒，不 clamp 会瞬移。
- 粒子/飘字等纯装饰运动也乘 dt（不乘会在高刷下加速消失，视觉不一致）。

### P1-A 打气球 `src/composables/useBalloonEngine.ts`

循环在 `gameLoop()`（约 241 行，`update(); render(); animationId = requestAnimationFrame(gameLoop)`）。改动点：

1. `update()` 改签名 `update(dt: number)`，`gameLoop` 里算 dt 传入。
2. 气球上升 `balloonList[i].y -= balloonList[i].speed`（约 323 行）→ `-= balloonList[i].speed * dt * 60`。
   **乘 60 的原因**：原 speed 语义是"px/帧@60Hz"（levelDefaults `moveSpeed: 1~6`），乘 60 保持 60Hz 屏幕行为完全不变（等价重构的硬要求）。
3. 子弹 `bullet.y -= bullet.speed`（约 337 行）→ 同样 `* dt * 60`（bullet.speed=10）。
4. 粒子 `spawnParticle` 运动与生命周期、飘字上浮——找到对应 `+= speed` / `-= alpha` 递减处同乘 `dt * 60`。
5. `spawnTimer = setInterval(spawnBalloon, levelConfig.value.spawnRate)` **不动**。

### P1-B 接水果 `src/pages/fruit/index.vue`

循环 `gameLoop()`（约 262 行）。改动点：

1. 同标准写法加 dt；`update()` 改 `update(dt)`。
2. `fruit.y += fruit.speed`（约 270 行）→ `+= fruit.speed * dt * 60`（fallSpeed 2~9，原 px/帧@60Hz 语义）。
3. 篮子移动逻辑若为"每帧位移"同样乘 dt；若为鼠标/触摸绝对定位则不动（先读代码确认，`moveHandler`/`touchHandler` 是绝对定位就不动）。
4. 粒子 `particles.push({ ... speed })` 的下落/淡出递减乘 dt。
5. `spawnTimer` setInterval 不动。

### P1-C 打砖块 `src/pages/brick/index.vue`

循环 `gameLoop()`（约 264 行，**顶部有 gameEnded/paused 守卫——这段守卫是历史 bug 修复（球掉落后 rAF 泄漏每帧扣命），必须原样保留**）。改动点：

1. 同标准写法加 dt（守卫之后、update 之前算）。
2. `ballX += ballVX; ballY += ballVY`（约 279-280 行）→ 乘 `dt * 60`。**先找到 ballVX/ballVY 的赋值处**（发球/反弹逻辑），确认其量纲也是 px/帧@60Hz 再乘；ballSpeed 公式来自 levelDefaults `ballSpeed` 字段，60Hz 校准语义不变。
3. 球拍是鼠标跟随（`movePaddle` 事件驱动）不动。
4. 粒子若有同乘。

### P1-D 坦克大战 `src/composables/useTankEngine.ts`

一处：`update()` 内 `if (moveDirection !== 0) { player.x += moveDirection * player.speed; ... }`（约 310-313 行）→ `player.x += moveDirection * player.speed * dt * 60`。dt 变量本函数已有（约 307 行 `const dt = (now - lastFrameTime) / 1000`，**注意这里没有 0.05 clamp，顺带补上 `Math.min(..., 0.05)`**）。player.speed 来源核对 levelDefaults tank 公式，保持 60Hz 等价。

- `npx vitest run src/__tests__/composables/` 全绿（useBalloonEngine/useTankEngine 有既有测试）。
- 手动验证（浏览器 dev 面板）：`Ctrl+Shift+P` → 无；用代码方式：在 gameLoop 前临时插入 `let f=0;setInterval(()=>console.log('fps',f),1000);f++`——**验证完必须删掉**。或者更简单：Chrome devtools Rendering → FPS meter 观察游戏节奏与 60Hz 时一致即可。
- **等价性自检**：在 60Hz 环境（普通显示器）下每款游戏玩一关，节奏应与改动前无肉眼差异。

## P2：登录过期静默失败修复

### 问题定义（已实测+读码确认）

`src/utils/request.ts` 401 拦截器：刷新失败路径只调 `userStore.logout()`（清 storage），**无跳转、无提示**。用户停留原页，所有操作持续 401 静默失败。实测场景：token 过期后点"创建房间"，界面零反应（错误被大厅页 catch 进 errMsg，但用户早已看不懂技术报错）。

### 改动（仅 `src/utils/request.ts` 一处 + 可选 toast）

1. 刷新失败终态处（`if (status === 401) { userStore.logout(); }` 附近）增加：
   - `showToast('登录已过期，请重新选择角色', 'error')`（`@/utils/toastBus`，项目已有，App.vue 已挂载）。
   - 跳转：`location.hash = '#/profiles'`。
   - **带 redirect 回跳**：当前 hash 非 `#/profiles` 时，改为 `#/profiles?redirect=<encodeURIComponent(当前完整 hash 去掉 '#')>`。回跳消费逻辑已存在（profiles 登录后读 `route.query.redirect`，房间邀请深链同款机制，勿重复实现）。
   - **防循环**：当前已在 profiles 页时不跳转不 toast（登录页自身的 401 静默即可）。
   - **防重复触发**：模块级 `let authExpiredHandled = false` 标记，处理后置 true；用户成功登录（可监听 store setTokens）时复位。避免同页多个并发 401 弹 N 个 toast。
2. `logout()` 的 import 链不动；userStore 逻辑不改。

### 验证

- 手动：登录 → localStorage 手动把 `token` 改成垃圾值且把 `refresh_token` 也改成垃圾值 → 点任意需要鉴权操作 → 应看到 toast + 跳 profiles → 登录后自动回跳原页。
- 既有 `src/__tests__/utils/request.test.ts` 全绿（其中"should clear token on 401"用例保持通过；如断言因新增 toast/跳转需要补充，是**追加**断言不是修改）。
- 回归冒烟：正常登录 → 建房 → 进房，确认刷新成功路径（access 过期但 refresh 有效）依然无感自愈。

## P3：打磨池（每项独立、低风险、按序做）

### P3-1 消消乐数字主题四色化

- 文件：`src/composables/useMatch3Engine.ts:22`，`THEMES[0]` 现为 `['0️⃣','1️⃣',...,'5️⃣']` 全靠 keycap emoji 自带蓝色，方块底色统一（实测截图确认全蓝、区分度依赖读数字，5 岁不友好）。
- 改法：**渲染层按 emoji 索引给方块底色**。找到渲染 tile 的位置（engine 的 render 或页面 `.vue` 的 CSS class），数字主题时底色数组 `['#FF8F8F','#FFB74D','#FFF176','#AED581','#80CBC4','#90CAF9']`（红橙黄绿青蓝，低饱和护眼，与项目配色原则一致）；其他主题维持现状。
- 实现 hint：可给 tile 增加 `colorIndex` 字段（=emoji 在 theme 数组的下标），渲染处查表。**不要**换掉 keycap emoji 本身（语音读题/其他逻辑可能引用）。
- 验证：进入 match3 第 1-4 关（数字主题区间），六种数字底色各不相同；`useMatch3Engine` 既有测试全绿。

### P3-2 快乐连线页面布局居中

- 文件：`src/pages/match/index.vue`（`min-height: 100vh` 在 395 行附近）。实测下半屏大片空白。
- 改法：页面根容器改 flex 纵向 + 内容区 `flex: 1` 垂直居中（参照 memory-game 的 `height:100vh + grid-auto-rows:1fr` 一屏无滚动模式，但 match 卡片少，居中即可）：
  ```
  根容器: min-height:100vh; display:flex; flex-direction:column;
  游戏区域: flex:1; display:flex; flex-direction:column; justify-content:center;
  ```
- 验证：1280×720 与手机竖屏 375×667 两档视口截图，配对卡居中、无滚动条。

### P3-3 数学小怪兽单物件放大

- 文件：`src/pages/math/index.vue` 物件渲染处（物件 emoji 来自 `src/composables/useMathEngine.ts:30` COUNT_ICONS；渲染 font-size 在页面 style，实测单物件时约 30px 偏小）。
- 改法：物件 font-size 改为**随数量缩放**：`1~3 个: 64px`，`4~6 个: 52px`，`7~10 个: 44px`（实现：内联 style 绑定或 computed class）。多物件时保持现尺寸避免撑爆容器。
- 验证：答一题 1 个物件、一题 7+ 个物件，视觉都清晰且不溢出物件框。

### P3-4 对战坦克障碍加纹理

- 文件：`src/components/battle/TankGame.vue:260`，障碍 `ctx.fillStyle = '#8d99ae'` 纯色矩形（实测与 `#eef3ea` 地面对比度尚可但缺乏质感，孩子反馈"分不清能不能穿过"）。
- 改法：在障碍矩形内叠加简单砖纹（两三条深色描线 `#6b7688`，或顶边高光 `#a5b1c2` 2px），纯 canvas 绘制、不动碰撞逻辑与 OBSTACLES 坐标。**禁止**改 `hitRect`/碰撞判定。
- 验证：开局截图障碍有纹理；坦克撞障碍行为不变（跑 `tests/ws-tank.mjs` 15 项全绿确认协议无漂移——虽然本改动纯前端，跑一遍安心）。

### P3-5 单机坦克键盘支持

- 文件：`src/pages/tank/index.vue` + `src/composables/useTankEngine.ts`（引擎已有 `moveLeft/moveRight/stopMove`，601 行附近还有 `startMove(e)` 按位置定向——键盘复用 moveLeft/moveRight 即可）。
- 改法：页面 `onMounted` 注册 `keydown/keyup` 监听（**挂 document，window 会被游戏画布焦点问题吞**）：
  - `ArrowLeft/a` → `engine.moveLeft()`，`ArrowRight/d` → `engine.moveRight()`，keyup 任一 → `engine.stopMove()`。
  - `空格/ArrowUp/w` → `engine.fire()`（keydown 触发，注意 repeat 去抖：`e.repeat && return`）。
  - `onUnmounted` 移除监听（命名函数引用，不能匿名）。
  - **快捷键冲突检查**：先 grep `keydown` 全项目确认坦克页无既有监听；暂停键 P 如已被 PauseMenu 占用则跳过不加。
- 验证：键盘左右移动+开火；手机触屏按钮不受影响；暂停/护眼休息弹层弹出时键盘不响应（引擎 moveLeft 有 `if (paused.value) return` 守卫，确认 fire 也有同款）。

### P3-6 接水果第 1 关节奏校准

- 文件：`src/utils/levelDefaults.ts:118-124`：`fruit: spawnRate max(1000-(l-1)*70, 380), fallSpeed min(2+(l-1)*0.5, 9), targetScore 100+(l-1)*50`。
- 实测：第 1 关 60Hz 下节奏合理（慢速稳定）；但 targetScore=100 配合每果 10 分=接 10 个，学龄儿童第一关 10 连接略难。**仅调一项**：`targetScore: 80 + (l-1) * 50`（第 1 关接 8 个）。
- **连锁检查（必做）**：
  1. 后端 `LEVEL_FIELDS`/admin 面板 targetScore 覆盖是否允许此字段——只是值变化不改字段名，无契约影响；
  2. 全局 grep `targetScore` 确认 fruit 消费处无硬编码 100；
  3. e2e 若有 fruit 相关 spec（`grep -rn fruit tests/`），跑一遍。
- 验证：第 1 关接 8 个通关；第 2 关 130 分正常。
