## 0. 合规红线（先说死）

两款游戏天然带博弈属性，本项目**只做桌内虚拟积分**：

- 积分只存在于**房间内存**（进桌发 1000，房间解散即清空），**不入库、不持久、无充值/提现/兑换**。
- 结算只显示本桌输赢与排名，不联动星级/等级/排行榜（儿童侧体系完全隔离）。
- 若以后想记"战绩"，只记场次数与最高积分，不做净盈亏排行（防止变成赌桌排名）。

## 1. 通用设计（两款共用）

### 1.1 货币与多轮局

| 项 | 决定 |
|---|---|
| 桌面积分 | 进桌每人 1000 分，存 `room.game`（handler 内存态），rematch 连续（换局重发） |
| 一局 playing | 包含多个 hand（先例：答题一局 10 题）；结束条件见各游戏 |
| ended 排名 | 按剩余积分降序，`game_over.winnerSeat` = 积分最高者座位 |
| 破产 | 积分归零者标记 `busted`，保留座位显示"破产"，不再参与后续 hand；全员只剩 1 人有分 → 提前 ended |

### 1.2 复用底座清单（两款相同）

1. `games/types.ts`：`GameType` 加 `'blackjack' | 'zjh'`
2. `games/blackjack.ts` / `games/zjh.ts`：handler（create/start/onPlayerQuit/onMemberOffline/onAction/serializeFor）
3. `games/registry.ts`：登记 → **大厅列表自动上架**（battle/index.vue 的 games 来自 API，无需改前端列表）
4. `room.vue`：事件 handler + `playingStatusText`/`overText`/`memberState` 加 gameType 分支；`.actions` 区对这两款隐藏"认输"（对局中退出=按弃牌/停牌离开）
5. `GamePanel.vue`：挂载 `BlackjackGame.vue` / `ZjhGame.vue`
6. 牌面渲染：纯 CSS 卡片（♠♥♦♣ + 字符点数），复用 UNO 的 CSS 卡片思路，不引图片素材
7. 测试：`tests/ws-blackjack.mjs`、`tests/ws-zjh.mjs`（沿用现有 6 套的 Client/waitNew 基建）

### 1.3 超时策略（防挂机）

沿用各游戏先例：玩家操作超时自动执行**保守动作**（21点=停牌；炸金花=弃牌），阶段推进由 handler 定时器驱动（room.timers 登记，销毁即清）。环境变量支持缩短时长供测试（先例：SPY_TALK_SECONDS）。

## 2. P6：21点（blackjack）

### 2.1 玩法定稿

- **人数**：2~5 人（1 庄 + 1~4 闲）。
- **庄家**：**玩家轮流坐庄**（推荐，朋友局更有对抗感；备选"系统庄家"不推荐——少了心理博弈）。首局座位 0 坐庄，之后按座位轮转。
- **牌堆**：每 hand 新洗 1 副 52（无王），不复用上一手牌（休闲局不做记牌对抗）。
- **点数**：A=1/11 自动取优（软点），J/Q/K=10，其余按面值；>21 爆牌。
- **玩家动作**：要牌（hit）/ 停牌（stand）/ 加倍（double，首两张后可加一次，注×2 且只再要一张）。**不做**分牌/保险/投降（控制复杂度，朋友局用不上）。
- **庄家规则**：闲家全部停牌/爆牌后，庄家亮暗牌，自动"<17 必须要牌，≥17 停牌"（含软 17 停牌）。
- **赔率**：玩家 Blackjack（首两张 21）赢 1.5 倍注；普通赢 1 倍；平局退注；输 1 倍；加倍翻倍计算。庄家不押注，直接按闲家输赢记账。
- **下注**：档位 10/20/50/100（不超过持币），超时默认下 10。
- **一局结束**：满 8 个 hand，或只剩 1 人有积分，或玩家破产过半（≥一半玩家 busted）→ ended。

### 2.2 状态机

```
playing
 └─ hand 循环（round: 1..8）
     betting（15s，全员下注）
     → dealing（发牌：闲家2明，庄家1明1暗）
     → acting（闲家按座位轮流 hit/stand/double，20s/人，超时=停牌）
     → dealer（庄家自动要牌，逐张广播，节奏 800ms/张）
     → settle（广播各家结果与积分变化）
     → 下一手（庄家=下一座位）或 ended
```

### 2.3 协议增量

C→S（onAction）：
| t | 载荷 | 校验 |
|---|---|---|
| `blackjack_bet` | { amount } | betting 阶段、非庄家、amount ∈ 档位且 ≤ 持币 |
| `blackjack_hit` | - | acting 阶段、轮到自己、未爆未停 |
| `blackjack_stand` | - | 同上 |
| `blackjack_double` | - | 仅首两张后、持币足够 |

S→C（广播/点对点）：
| t | 说明 |
|---|---|
| `blackjack_phase` | { phase, round, bankerSeat, deadline } |
| `blackjack_deal` | { hands: 各家明牌, bankerUpcard } —— 暗牌走 serializeFor，不广播 |
| `blackjack_action` | { userId, action, card? } 要牌时带新摸的明牌 |
| `blackjack_settle` | { results: [{userId, delta, chips, outcome}], bankerReveal: [cards] } |

### 2.4 serializeFor（按人隐私）

```ts
{
  round, bankerSeat, chips: [...], handCount,
  myCards, myStake, myDoubled,
  bankerUpcard,                 // 庄家暗牌只给庄家本人
  bankerCards: isBanker ? st.banker.cards : null,
  phase, deadline,
  others: [{userId, cardCount, stake, busted, stopped}],  // 别家只给张数+状态
  ended: { ranking } | null,
}
```

### 2.5 前端

`BlackjackGame.vue`：
- 顶部：庄家标识 + 手数（第 X/8 手）；积分条（每人当前积分，复用座位格已有展示）
- 庄家区：明牌 + 暗牌背面（庄家视角翻开）；点数徽标（软点显示如"软 17"）
- 自己手牌区：大卡片 + 点数 + 动作按钮组（下注档位 / 要牌·停牌·加倍）
- 结算浮层：本手各家输赢动画（+20/-10），2s 后自动进下一手
- CSS 卡片组件与 UNO 复用一套样式变量

## 3. P7：炸金花（zjh）

### 3.1 玩法定稿

- **人数**：2~6 人（推荐 3~6，min 2）。
- **牌**：52 张无王，每手新洗；每人 3 张（私密）。
- **牌型**（大→小）：豹子（三条）> 顺金（同花顺）> 金花（同花）> 顺子 > 对子 > 散牌（单张最大 A）。
  - 顺子边界写死：**QKA 最大，A23 算最小顺子**；234/K 中间按 A=14 或 1 取更优。
  - 特殊 235（散牌 2-3-5 不同花反杀豹子）**默认关闭**（待确认，见 §5）。
  - 同型比点：从大到小逐张比，对子先比对子点再比单张。
- **轮庄**：上一手庄家的下家（首手座位 0）。
- **注码规则**：
  - 底注固定 10（开局每家自动扣入池）；
  - 闷家（未看牌）跟注 = 当前单注；看家跟注 = **2×当前单注**；
  - 加注档位：+10 / +20 / +50（以"看家价"为基准，封顶**单注 100**）；
  - 前 2 轮禁止比牌；比牌费 = 2×当前单注（闷家也按看家价付），指定一名存活对手私下比牌，**输者立即弃牌，胜者继续**；
  - 第 6 轮结束或单注触顶后下一轮**强制全员开牌**；
  - 筹码不足以跟注 → all-in（投入全部，视作跟注，简化处理）。
- **一局结束**：只剩 1 人有积分（其他人破产）或打满 15 手 → ended。弃牌到只剩 1 人 → 直接赢池进下一手。

### 3.2 状态机

```
playing
 └─ hand 循环（round: 1..15）
     ante（自动扣底注，广播）
     → dealing（3 张私发）
     → betting（从庄家下家轮流，25s/人，超时=弃牌）
         动作：look / call / raise / fold / compare {target}
         终止：只剩 1 家 → win pot → settle；触发强制开牌 → showdown
     → showdown（存活者全部亮牌，服务端判型）
     → settle（赢家收池；广播各家亮牌与积分变化）
     → 下一手（轮庄）或 ended
```

### 3.3 协议增量

C→S：
| t | 载荷 | 校验 |
|---|---|---|
| `zjh_look` | - | 未看过牌才有效（免费，状态置 seen） |
| `zjh_call` | - | betting 阶段、轮到自己 |
| `zjh_raise` | { amount } | amount ∈ {10,20,50}，加注后单注 ≤ 封顶 |
| `zjh_fold` | - | - |
| `zjh_compare` | { target } | round ≥ 3、target 存活且非自己、持币足够 |

S→C：
| t | 说明 |
|---|---|
| `zjh_deal` | 每人 { t:'zjh_deal', cards } **点对点私发**（先例：spy_deal） |
| `zjh_action` | { userId, action, stake } —— 看牌动作只广播"已看牌"，不泄露给谁 |
| `zjh_compare_start` | { from, to, cost } 广播（大家知道有人比牌） |
| `zjh_compare_result` | 双方点对点（含牌面），其余人只收到 `{ winner }` 匿名结果? —— 推荐：广播胜者身份（输者已弃牌大家看得到），**牌面只给双方** |
| `zjh_showdown` | { reveals: [{userId, cards, type}] } 全员亮牌 |
| `zjh_settle` | { winner, pot, deltas } |
| `zjh_phase` | { phase, round, dealerSeat, stake, deadline, aliveCount } |

### 3.4 serializeFor（按人隐私）

```ts
{
  round, dealerSeat, phase, deadline,
  pot, stake, roundNo,             // 当前单注与轮数
  myCards, seen,                   // 只发自己的牌；看没看牌是公开状态
  others: [{userId, blind(闷/看), folded, chips, betTotal}],  // 不发张数
  compareLock: 轮次限制,
  ended: { ranking } | null,
}
```

### 3.5 前端

`ZjhGame.vue`：
- 牌桌布局：自己的 3 张大牌（未看牌显示背面，点"看牌"翻牌动画）+ 其余玩家小卡背（显示 闷/看/弃/已出局 徽标）
- 池子与当前单注显示；轮次进度（X/6，触顶倒计时提示）
- 动作条：看牌 / 跟注（显示价）/ 加注（三档弹出）/ 比牌（进入选人模式，点存活对手头像）/ 弃牌
- 比牌结果：双方视角显示对方牌面 + 胜负；旁观者只显示"X 与 Y 比牌，X 胜"
- settle 浮层同 21点

## 7. 积分与生涯基建（两款牌类的地基，全对战游戏共用）

### 7.1 数据模型

- `users` 加列 `battleChips INTEGER DEFAULT 1000`（syncMissingColumns 自动补列）
- 新表 `battle_records`：id / userId / gameType / result（win·lose·draw·rank:N）/ chipsDelta / chipsAfter / createdAt（Sequelize Model sync 自动建表）

### 7.2 结算规则

| 游戏 | 结算 |
|---|---|
| 21点 / 炸金花 | 每手实时入账（桌内积分=账号积分，无二次换算） |
| 五子棋/答题/画猜/卧底/UNO | 局终按排名：第 1 名 +30、第 2 名 +15、第 3 名起 +5；平局各 +10（常量集中在 chips.ts 可调） |

- 结算入口：`wsServer.endGame()` 统一调用 `settleBattleChips(room)`——handler 有 `ranking` 用排名，否则胜者在前按座位排；写库失败 catch + log，不影响对局广播。
- 破产保护：进房时 `battleChips < 100` 自动补足 1000（后台发放之外的救济线）。
- 记录写入受建房开关 `career`（默认开）控制：关 = 只动积分不写流水。

### 7.3 接口

- `GET /api/user/battle/career`：当前积分 + 各游戏（场次/胜场/胜率/最佳排名）+ 最近 20 条流水
- 管理端 `PUT /api/admin/users/:id/chips`：{ delta } 或 { set }，写操作日志
- 个人中心 /profile 增"对战生涯"卡：积分、分游戏战绩、最近流水；后台用户面板增加积分列与"发积分"

### 7.4 房间配置（建房时设置，期间不可改）

`POST /api/room` 载荷增加 `config`，roomManager 校验后存 `room.config`，handler.start 读取：

```ts
blackjack: { bankerMode: 'rotate'|'winner'|'keep', roundLimit: 8, career: true }
zjh:       { special235: true, timeoutFold: true, roundLimit: 15, career: true }
通用可选:   career（五款竞技游戏也默认开）
```

## 8. 消消乐（match3，儿童第 10 款游戏）

- 玩法：8×8 emoji 网格，点选相邻两枚交换，横竖 ≥3 连线消除，上方掉落补位，连锁 combo 加分（×2 递增）；无可消除局面自动重排并提示
- 主题按关卡轮换（floor((level-1)/3)%4）：数字 0️⃣1️⃣…9️⃣ / 动物 🐱🐶🐰🐼🦊🐸🐷🐵 / 植物 🌳🌸🌻🌵🍀🍁🍄🌴 / 水果 🍎🍇🍉🍓🍑🍍🥝🍌
- 目标：限定步数内达到目标分 → 通关；成绩 = 剩余步数（越小越好，加入 GAME_RULES 白名单）
- 难度公式（levelDefaults）：目标分 = 300 + (level-1)×80；步数 = 20 − floor((level-1)/3)，下限 12
- 登记清单（新游戏五处+）：levelDefaults 公式 / gameMeta GAMES / 后端 LEVEL_FIELDS / 路由 / 首页卡片+SVG / GAME_RULES 白名单 / PauseMenu 暂停 / useGameProgress / applyLevelConfig / 护眼事件
- 页面 /match3，DOM 网格 + CSS 过渡动画（交换位移、消除缩放淡出、掉落下落），音效复用 playMatch
