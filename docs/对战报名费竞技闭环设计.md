# 对战报名费竞技闭环 — 规则设计稿（待拍板）

> 状态：**待拍板**。本文档只定规则与技术边界，不含代码改动。
> 背景路线图：A（斗地主）✅ → C（家庭积分榜）✅ → **B（本设计稿）**。
> 作者注：所有金额单位=对战积分（battleChips，永久跟随），不是星级。

## 一、目标与范围

**目标**：给对战加"押积分"玩法——建房者设报名费，全员入池，按名次分奖池。让积分有输赢张力，刺激对战活跃。

**适用范围（关键决策①）**：

| 类型 | 游戏 | 是否参加 | 原因 |
|---|---|---|---|
| 排名制竞技 | 五子棋/答题/你画我猜/谁是卧底/UNO/坦克对决 | ✅ 参加 | 现有结算=平台发固定奖金（1st 30 / 2nd 15 / 3rd 5，积分凭空产生），无对赌张力 |
| 牌类零和 | 21点/比大小/斗地主 | ❌ 不参加 | 本身就是积分对赌（每手实时转移零和），加报名费=双重计费 |

## 二、规则设计

### 2.1 报名费档位（决策②）

建房表单新增「报名费」选择：**0（默认）/ 50 / 100 / 200**。

- 0 = 现状（纯奖励制），报名费仅显式开启时生效
- 封顶 200：防"倾家荡产一局"与多账号互刷；救济线（<100 补 1000）仍兜底
- 房主开房即锁定，游戏期间不可改（沿用 config 白名单惯例）

### 2.2 扣费与退款时机（决策③，建议 B 方案）

| 时机 | A：开局扣 | B：加入房间即扣（推荐） |
|---|---|---|
| 防白嫖（建房不解散） | 差（开局前可白看） | 好 |
| 余额校验点 | 开局时 | 加入时 + 开局时复查 |
| 实现复杂度 | 低 | 中（加入/退出/解散都要处理退款） |

**推荐 B**：加入房间瞬间校验 `battleChips ≥ 报名费`（不足→拒绝加入并提示），通过即预扣入奖池；退出/掉线判离 **不退**（弃赛惩罚）；房主解散房间 **未开局全退**；平局/异常终局 全退。

### 2.3 奖池分配（决策④，二选一）

奖池 = 报名费 × 参赛人数。

- **方案甲·赢家通吃**（推荐，简单直接）：第 1 名拿全部奖池。
  - 2 人局天然合理；多人局（UNO 6 人/答题 8 人）第二名颗粒无收，但规则易懂。
- **方案乙·按名次加权**：1st 70% / 2nd 30%（3 人以上局）；2 人局退化为赢家通吃。
  - 更平滑，但多人局（8 人答题）只覆盖前两名，其余仍颗粒无收，解释成本高。

> 未开报名费的房间保持现状（平台发 30/15/5）。**开报名费的房间跳过固定奖金**（settleGameChips 分支），避免积分通胀。

### 2.4 与现有系统的交互

| 系统 | 交互 |
|---|---|
| 救济线 | 余额 < 报名费 → 禁止加入该房（提示"积分不够报名费，先玩无报名费房间或等明日救济"）；救济补额照常 |
| 单账号单桌 | 已有机制直接复用 |
| 生涯流水 battle_records | delta 天然体现（奖池分配的 ±），无需新字段；`type` 沿用 win/rank:N |
| 家庭积分榜 | 不受影响（余额排序） |
| 观战者 | 不扣费不参与分配 |
| rematch 再来一局 | **每局独立扣费**（开局即扣、终局即分，无跨局累积） |

### 2.5 边界矩阵

| 场景 | 处理 |
|---|---|
| 建房后无人加入，房主解散 | 全员（=房主）退款 |
| 加入后开局前退出 | 退款（未开局） |
| 对局中退出/掉线 60s 判离 | 不退（弃赛，奖池照分） |
| 认输 | 不退（同上） |
| 平局（gomoku winner=3 等） | 奖池全额退还各人 |
| 人数不足强制终局 | 已扣者按当期名次分池（handler onPlayerQuit 现语义不变） |
| 结算时 applyChipDelta 失败 | 现有 3 次退避重试+logError 告警；奖池金额持久化在 room 内存，进程重启=房间销毁，走解散退款语义（未终局退款） |

## 四、风险与开放问题

- **多账号互刷**：家庭成员真实人数少（≤10），互刷收益受 200 封顶与救济冷却限制，风险可控；不上风控
- **孩子误开高额房**：报名费默认 0；是否需要"家长中心开关：允许报名费玩法"？（❓待拍板——建议加开关，默认允许）
- **2 人局节奏**：五子棋一局可能 <1 分钟，每局扣费会快速滚动积分——正是设计意图，但注意救济线节奏
