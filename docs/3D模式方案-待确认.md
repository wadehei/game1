> 目标：给现有游戏增加 3D 模式提升体验。**核心原则：3D 是"模式"不是"替换"**——
> 每款游戏保留 2D 原版，3D 作为可切换的第二形态（斗地主已示范：/doudizhu 与 /doudizhu-3d 并存），
> 手机 WebGL 不可用/低帧率时自动回退 2D，永不因 3D 把游戏搞坏。

## 二、技术路线分三层（按成本从低到高）

- **L1 · CSS 3D**：纯 CSS transform/perspective，零新依赖、手机 GPU 合成最流畅。适合"翻、弹、按"类交互。
- **L2 · Three.js 真场景**：复用 three-vendor 分包。适合需要空间感/光影/模型的游戏。
- **L3 · 2.5D 增强**：保持现有 2D，加视差/光影/粒子。适合 3D 化无益但有"廉价感"的游戏（兜底选项）。

## 三、逐游戏评估（12 单机 + 9 对战）

### 🟢 强推（感知收益大、与玩法天然契合）

| 游戏 | 方向 | 路线 | 一句话理由 |
|---|---|---|---|

| 消消乐 match3 | 3D 方块+消除翻转爆裂（L2） | Three.js | 消除类 3D 反馈爽感提升明显；已有对象池基础 |

### 🟡 可选（有收益但不急）

| 游戏 | 说明 |
|---|---|
| 打砖块 brick | 3D 砖块+球阴影有提升；玩法本质 2D，放二期后视情况 |

### 🔴 不做（3D 化无益甚至有害）

- **拼图**：3D 化让对位操作变难（2D 精确点击是玩法核心）
- **动物数独 / 快乐连线**：信息密度型，3D 只会分散注意力
- **数学小怪兽**：数数物件 3D 化无收益，保持清晰第一
- **你画我猜（对战）**：画布必须 2D
- **答题对战 / 谁是卧底**：纯信息流，无空间概念

## 四、统一护栏（所有 3D 模式强制遵守）

1. **双模式并存**：路由并行（如 /memory 与 /memory-3d），游戏内加 2D/3D 切换按钮；默认 2D，家长可在设置里设默认
2. **自动降级**：WebGL 检测失败 / 连续低帧（<25fps 持续 5s）→ 提示并回退 2D
3. **性能红线**：pixelRatio ≤ 1.5、低多边形+纯色光照（不上贴图模型）、对象池复用（match3 已有基础）
4. **逻辑零重复**：3D 版只换渲染层，游戏逻辑/进度上报/难度系统全部复用现有 composables（ddz 模式强制执行）
5. **加载体验**：three-vendor 已分包；3D 场景进入前加"加载中"过渡，避免白屏突兀
